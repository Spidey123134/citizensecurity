# Fases de CITIZENSECURITY

La entrega actual es **0.4.0**, código Android **7**, para `main` y la etiqueta [v0.4.0](https://github.com/Spidey123134/citizensecurity/releases/tag/v0.4.0). Conserva la interfaz, el splash y las herramientas de [0.2.1](https://github.com/Spidey123134/citizensecurity/releases/tag/v0.2.1), código Android **6**. El botón de desarrollador y **admin / admin** siguen dando acceso local a recepción, validación y pruebas de coordenadas de fases 1 y 2. **Fase 3 / 0.3.0 sigue en Unreleased**; la entrega 0.4 completa la consulta técnica por folio, sin añadir su pantalla.

El [plan del proyecto](PLAN_DEL_PROYECTO.md) relaciona estas fases técnicas con el PDF original. La consulta local de fase 4 avanza sobre organización y lectura del apartado 4.4; las cuentas, los reportes propios por usuario y los cambios administrativos de estado siguen pendientes.

**Implementado**, **probado** y **revisado por el usuario** son estados distintos. La base de lógica y datos ya tiene código y pruebas; eso no significa que el usuario haya aceptado cada paso. Después de revisar la fase actual se elige el siguiente incremento.

## Reparto y siguiente paso

Las interfaces, el menú, la navegación y el login corresponden al compañero (`vazdavr-sudo`). El acceso local de demostración `admin / admin` fue solicitado por el usuario. La autenticación real sigue pendiente y se acordará antes de conectarla a servicios o cuentas. Los contratos y la composición compartida de dependencias se coordinan entre ambos, según [Trabajo del equipo](TRABAJO_EQUIPO.md).

El usuario autorizó acoplar la interfaz a nuestra lógica: el puente técnico de [Acoplar interfaz](ACOPLAR_INTERFAZ.md) y el de consulta de [Fase 4](FASE_4.md) están implementados y comprobados. El compañero puede conectar después su formulario y controles de consulta. Las pruebas técnicas no aceptan funcionalmente esas pantallas ni entregan fase 3. Su código adelantado se conserva para `0.3.0 — Unreleased`. La integración visual de Google Maps sigue siendo una línea acordada posterior.

El splash y el login visual del compañero se conservan. La entrega oficial `0.2.1` aprobó 14 JVM de app y 9 instrumentadas SQLite; sus 32 de dominio conservaron el resultado mediante `UP-TO-DATE`. [Funciones publicadas](FUNCIONES_PUBLICADAS.md) describe los controles conservados en 0.4 y la comprobación de consulta con Gradle; [Validación](VALIDACION.md) registra la prueba visual del botón y del acceso de demostración. Las herramientas del botón no incorporan guardado ni consulta.

La comprobación técnica de `0.4.0` aprobó 24 JVM de app (8 de guardado, 8 de consulta y 8 de herramientas), 32 de dominio ejecutadas de nuevo y 10 instrumentadas en API 37; los JSON de consulta y guardado fueron correctos. Lint y compilación debug/release terminaron sin errores, con datos sin incidencias y las 13 advertencias visuales previas. Las dos regresiones de cancelación JVM fallaron antes de la corrección y aprobaron después. El usuario autorizó el cierre de esta entrega para `main` y `v0.4.0`; eso no registra aceptación funcional. La consulta visual y su rotación real siguen pendientes porque la pantalla corresponde al compañero.

## Alcance pendiente de acuerdo

La conexión de Google Maps requiere definir el SDK, proyecto de Google, clave y facturación antes de implementarla. Captura GPS, fotografías, sincronización, servidor, administración y notificaciones quedan pendientes de un nuevo acuerdo de alcance. El guardado actual es local. El proyecto anterior y su respaldo se conservan como referencia, y solo se reutilizan las partes necesarias para el incremento elegido.
